# 项目计划工作台（dsh-workbench-pm-plan）

给项目经理自己用的本机工作台：把一个平台项目里**多端（手机 / PAD / 小程序 / PC Web）**的项目、
需求变更工单、工作计划、跟进事项、**需求文档库**、风险和周季报放在一处管，不再散在记事本、表格和 Word 里。

只在本机开发和使用，不上架、不上传、不联网。

## 它解决什么

- 工作计划、工作事项跟进不系统：谁在做、做到哪一步、什么时候到期，没有一处能一眼看完。
- 周报 / 季报每次都要重新翻记录、重新拼。
- 项目下的**变更**与**迭代需求工单**散乱：没有台账，状态流转靠脑子记。

## 一次任务的核心流程

1. **进入**：在侧栏顶部的模式切换器里选「项目计划工作台」。没有会话、没有工作区也能直接看到整页业务面板。
2. **登记项目**：`新建项目` 填名称、模块、端、状态、负责人、起止日期、进度、说明。模块与端默认是
   （公司项目 / 移动端开发 / 日常工作 / 其他项目）和（移动手机 / 移动 PAD / 小程序 / PC Web / 其他），
   都能在顶栏 `设置` 里改名、增删、排序；历史数据里出现过的取值也不会丢，会继续出现在筛选项和下拉里。
3. **拆工单**：`新建工单` 记需求 / 变更 / 缺陷 / 技术任务，选类型、优先级、阶段（待评审 → 待排期 → 开发中 →
   联调中 → 测试中 → 待上线 → 已上线）、目标端、预估人日、期望截止。工单详情里有一排阶段按钮，点一下就能流转。
4. **排计划并持续跟进**：`新建计划` 关联到项目（可选关联工单），填负责人、起止、进度。计划列表可直接勾完成；
   每条项目/工单/计划都可以在详情里追加「进展 / 阻塞 / 决策 / 变更 / 上线」记录，形成时间线。
5. **看风险**：系统按本地日历日自动判定风险等级 —— 已逾期 / 阻塞 / 紧急（≤2 天）/ 进度风险（时间过半而进度落后 ≥30%）/
   临近（≤5 天）/ 未排期 / 正常 / 已完成。概览页顶部的一排智能视图卡，
   以及「风险」页，把需要马上处理的事按桶列出来。
6. **出文档**：`汇报` 页按当前数据一键生成**工作周报 / 季度汇报 / 项目状态汇报**的 Markdown 草稿，可复制或下载 `.md`
   （也可以在右侧「AI 会话」里让 Agent 接着加工或改写）。

7. **管需求文档**：`文档` 页先指定一个**本机文档库目录**（工作台只在你点按钮确认时才创建目录），然后导入
   文档或新建 Markdown。文档可以挂到项目/工单、标版本和标签；Markdown 与纯文本支持在界面里直接改写并保存，
   Word / Excel / PDF / 图片等调用系统默认程序打开。列表里磁盘上已不存在的文件会标红「找不到」，可重新导入。

**完成状态**：条目被标记完成、文档保存成功、或改动写入成功（顶栏显示「已保存 · 修订 N」）。
**失败恢复**：保存失败时界面保留当前内容并给出原因；版本冲突（另一个窗口改过）提示「重新加载」；数据文件损坏时拒绝覆盖。

## 界面结构

- **顶栏**：品牌 / 搜索 / 刷新 / 新建项目·工单·计划 / **设置** / AI 会话 / 保存状态。
  新建、示例数据、清空都收在顶栏和「设置」里，页面上没有常驻的侧边栏，八个页签独享整幅宽度。
- **页签**：概览 · 项目 · 工单 · 计划 · 文档 · 日历 · 风险 · 汇报。
- **筛选按页各管各的**：切页签不会把上一页的筛选带过去。
  - 概览：一排**智能视图统计卡**（在管 / 需关注 / 已逾期 / 本周到期 / 未排期 / 已完成，点一下就跳到项目页的对应视图），
    外加模块 / 端两个筛选条；本页的 6 个 KPI、风险环形图、模块与端负载、负责人负载、需要马上处理、本周七天看板、
    问一句都会跟着这个范围收窄。
  - 项目：模块 + 端筛选条，下面是按模块 / 端 / 状态分组的卡片墙，可展开子项。默认是**全量口径**，
    在管的和已完成的都在列表里。
  - 工单：模块 + **目标端**筛选条，列表 + 阶段看板。同样默认全量。
  - 智能视图只在概览里选：点概览的统计卡跳到项目页时，项目页会多出一枚**可点掉的视图标记**（例如「已完成 ✕」），
    点掉就回到全量；项目页与工单页本身不再摆智能视图筛选项。
  - 计划（列表 + 状态看板）、日历（月历，可翻月、回本月）、风险（分桶清单）、汇报（生成 / 复制 / 下载）始终看全量，
    不在页面里再筛一遍。
- **设置**：一个弹窗管所有可配置项 —— 模块与端的改名 / 删除 / 上下移 / 新增，以及示例数据与清空。
  模块改名会自动级联到所有项目和工单，旧名字不会变成孤儿数据。
- 点任何项目、工单、计划都会从右侧滑出详情抽屉；详情里可编辑、删除、追加进展。文档页的编辑用整页弹窗（写 Markdown 更舒服）。
- 「AI 会话」按钮把宿主提供的原生会话放进右侧抽屉；**面板自己不创建会话、不改写会话归属、不碰工作区**。

## 数据放在哪

```
$DSH_HOME/pm-plan/state.json
# 本机即：~/Library/Application Support/dsh-desktop/harness/pm-plan/state.json
```

- 写入是原子的（临时文件 + rename），带 `revision` 做并发检测；读取时统一收敛结构，旧数据不会导致崩溃。
- 卸载工作台**不会**删除这个目录；重新安装后数据还在。
- 想从零开始就自己移走或删掉这个文件，或在界面里点「清空」。

### 需求文档库

```
<你在界面里指定的目录>/
  index.json          # 文档索引：挂到哪个项目/工单、标题、版本、标签、备注
  手机银行/需求说明书.md
  手机银行/接口清单.xlsx
  ...
```

- 文档本体始终在你指定的本机目录，**不会上传到任何地方**；索引也写在该目录里，整个目录可以直接拷贝/备份/搬走。
- 工作台**不会自己建目录、不会猜位置**：默认建议 `~/Documents/项目计划工作台文档`，但必须由你点「建立文档库」确认。
- 界面里「移除」默认只从索引移除、**不动文件**；要真删文件需要单独点「同时删除本机文件」。
- 单个文件上限 32 MB，界面内文本预览/编辑上限 4 MB。
- 第一次进入且数据为空时会生成一份带「示例」标签的示例数据，点顶栏「设置」里的「清空」即可删掉。

## 接口

服务端只注册本工作台自己的路径前缀：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/pm-plan/state` | 读取 `{ revision, state }` |
| POST | `/api/pm-plan/state` | 整体保存，`revision` 不一致返回 409 |
| GET | `/api/pm-plan/health` | 返回 `{ ok, name, file, docs }`，用于确认服务端已加载 |
| GET | `/api/pm-plan/docs` | 列出文档库（含索引元数据、缺失标记） |
| POST | `/api/pm-plan/docs` | `{ action: 'root', root }`：建立/切换文档库目录（此时才 mkdir） |
| GET | `/api/pm-plan/docs/file?path=` | 读取文本内容（Markdown / 文本，供界面编辑） |
| POST | `/api/pm-plan/docs/file` | `{ kind: 'upload' \| 'write' }`：导入文件（base64）或保存文本 |
| POST | `/api/pm-plan/docs/meta` | 更新文档元数据（项目/工单/标题/版本/标签/备注） |
| POST | `/api/pm-plan/docs/action` | `{ action: 'open' \| 'delete' \| 'rename' }` |

统计、风险判定、周季报全部在纯函数里完成（`src/shared/`），所以服务端不依赖宿主其他服务，也不占用别人的接口路径。

## 安装（本机）

```bash
pnpm pack
dsh plugin --profile web add "$PWD"/dsh-workbench-pm-plan-*.tgz
```

装完重启 Harness（应用菜单 **Harness → 重启**，或 <kbd>⌘⇧R</kbd>），再到「工作台管理／已安装的工作台」确认条目并从左侧入口打开。
首次使用还需要在 **设置 → 通用** 里打开「启用工作台功能」（这是宿主的开关，工作台不能代替你打开）。

## 开发

```bash
pnpm install
pnpm build      # 把 src/ 打成单文件客户端模块 lib/client.js
pnpm test       # node:test：模型、风险、视图、汇报、存储、服务端路由、客户端渲染与交互
pnpm check      # 按规范第 3 节校验包格式
pnpm verify     # build + test + check
```

### 客户端构建的约束

Desktop 不会替你构建客户端，`lib/client.js` 必须是已构建好的单文件模块。`scripts/build-client.mjs` 只支持一个很小的
语法子集：多行 `import ... from '...'`、`export const/function/class`、`export { ... }`、`export { ... } from '...'`、
`export default`。相对路径的模块会被内联成模块表；裸包名（`react`）交给宿主模块加载器的 `require`。
用到不支持的语法会构建报错，而不是产出坏包。

## 界面边界

- 注册为 `customFrame: true` 的业务整页：占满宿主分配的主内容区，内部用 flex 填满，不越界、不覆盖 Desktop 侧栏与
  「工作台管理」入口。会话按需从右侧抽屉展开，不默认占用半屏，也不自动创建会话。
- 样式优先复用宿主 `--dsw-*` 令牌（颜色、圆角、字体、按钮），跟随 Desktop 主题；布局用**容器查询**按业务容器宽度适配，
  窄窗口下弹窗、筛选条、统计卡会自动收成单列或横向筛选条。
- 不创建会话、不改写会话归属、不动工作区；所有依赖会话的动作都由用户把提示词复制到会话里完成。
